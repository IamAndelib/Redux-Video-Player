## Goal
The agent QA loop of QA.md, made concrete. It covers:
- roles and rubrics: visual against Figma and the brief, UX and accessibility, playback and formats, regressions
- a findings format with severity, evidence and the suspected file
- the loop itself: generate, run, triage, fix, re-run, with a round cap; unresolved items go to `GAPS.md`
- a per-PR QA report

Acceptance (ROADMAP): a dry run on a seeded bug finds, fixes and re-tests it.

## Dry run (T4, the acceptance)
On a throwaway branch `dryrun/q06-seeded`, never pushed and deleted after the run, one commit seeded a realistic
regression with a message that gives nothing away ("M1.5: simplify ButtonExt colour states"). It changed
`ButtonExt.qml:95` from `hovered: control.hovered` to `hovered: control.down`, so hovering gives no feedback.

| Step | What happened |
|---|---|
| Run | `qa.sh L1 L4`: **FAIL**, 12 checks, 1 failed: `l4.tst_ButtonExt` (day-hover, night-hover: "171 of 1350 pixels differ"); L1 9/9. |
| Triage | Two agents in parallel, given only the reports, logs, images and the diff command, not the seeded change. **QA triager:** F1 P1, product bug, `ButtonExt.qml:95`, "a hovered button keeps its Normal colours"; the hover grabs are byte-identical to the Normal baselines; don't regenerate baselines. **QA expert (regressions):** the same F1 P1 with the same evidence, plus "nothing explains the change". Both found F2 P3: stale failure images in `build/meson/l4/`, and `l4.run` reading "pass" beside "meson test exited 1". |
| Fix | The lead restored `hovered: control.hovered` (F1). |
| Re-run | `qa.sh L1 L4`: **PASS** 12/12, round 1 of 3. |

F2 was a real harness issue, fixed on this branch: `qa.sh` clears `build/meson/l4/` before a run (verified with a
planted stale file), and the runner row says it reported every test. The loop found, fixed and re-tested the seeded
bug in one round; the briefs' formats carried priority, evidence and the suspected file.
