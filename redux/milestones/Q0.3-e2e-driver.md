## Goal
Real user journeys in the real app, driven through AT-SPI by KDE's selenium-webdriver-at-spi inside the headless KDE
session; the first flows pass three runs in a row (issue #58).

## Research (T1, done)
- selenium-webdriver-at-spi pinned at `cb67767e` (GitHub mirror, sha256-checked): a Flask WebDriver server over
  pyatspi plus C++ helpers; `inputsynth` injects input through KWin's fake-input protocol (needs `KWIN_PID`). No
  releases, no Debian package; the Python client (selenium 4.29.0, Appium 4.5.1) is too new for Debian, so it goes in a
  hash-locked venv. `run.rb` is skipped: our `kwin-session.sh` does its job.
- Probe: VLC's QML UI already exposes a well-named AT-SPI tree (`Play/Pause`, `Progress`, time labels, `Play Queue`…).
- Playback oracle: MPRIS (`--control=dbus`, bus `org.mpris.MediaPlayer2.vlc`); UI checks through AT-SPI.
- The driver's NAME locator only finds visible or sensitive elements, so tests reveal auto-hidden controls first. A
  key press reveals them every time; pointer moves through KWin fake input revealed them only once per session.
- On Wayland, AT-SPI element positions are window-relative, so the driver's clicks only land when the window's
  content sits at (0, 0): a KWin rule and `QT_WAYLAND_DISABLE_WINDOWDECORATION=1` in `kwin-session.sh`.
- A track entry's accessibility action selects but doesn't toggle it; a real click does.
- D-Bus frees the MPRIS name asynchronously: a player started too soon after the last one registers as
  `org.mpris.MediaPlayer2.vlc.instance<pid>`, so each test class waits for its player to leave the bus.
- Every element the flows use already has an accessible name: no QML changes were needed.
- With `--start-time=9`, VLC treats the rest as the whole media: MPRIS Position runs from 0 and `mpris:length` is
  what's left (3 s for E06).
