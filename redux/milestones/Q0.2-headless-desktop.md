## Research
- **Prior art (adopted, ideas only):** KDE's [selenium-webdriver-at-spi](https://github.com/KDE/selenium-webdriver-at-spi)
  `run.rb` (AGPL-3, so no code copied): `dbus-run-session -- kwin_wayland --virtual --no-lockscreen
  --no-global-shortcuts --width --height --exit-with-session "<cmd>"` with `KWIN_SCREENSHOT_NO_PERMISSION_CHECKS=1`,
  `KWIN_WAYLAND_NO_PERMISSION_CHECKS=1`, a fixed keyboard layout and throw-away XDG dirs; AT-SPI bus started inside.
  xwayland-run's `wlheadless-run -c kwin` does the same.
- **ScreenShot2** (`org.kde.KWin /org/kde/KWin/ScreenShot2`, KWin 6.7.4 in sid): `CaptureWorkspace(a{sv}, h)` writes raw
  pixels to the pipe and replies with width, height, stride and QImage format; `gdbus` can't pass a file
  descriptor, so a ~25-line Python `Gio` client does it (the env var above skips the caller permission check).
- **Probes on SKYNET** (throw-away containers):
  1. `kwin_wayland` failed with "Operation not permitted": Debian sets `cap_sys_nice=ep` on it, which rootless Podman
     can't grant → `setcap -r` in the image (KWin then just runs without real-time priority).
  2. With that, the session starts and the QML smoke test runs in it as a Wayland client (OpenGL, llvmpipe).
  3. VLC crashed in `egl_gbm.c` `SwapBuffers` (NULL function in Mesa) when `/dev/dri` was passed through and
     `LIBGL_ALWAYS_SOFTWARE=1` forced software GL: issue #73 (P3, upstreamable).
- **Deterministic rendering on every machine:** `KWIN_COMPOSE=Q` (KWin's QPainter renderer, as in CI where there is no
  GPU) and VLC's `--vout=wl` (shared-memory Wayland output): its GL output would refuse llvmpipe (#72) and its GBM
  path crashes (#73). Qt's own UI still renders with OpenGL on llvmpipe.
- **New gaps:** none.
