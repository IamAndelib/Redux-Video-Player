## Goal
QA layer L4 (QA.md): each QML widget rendered alone in every state (normal, hover, pressed, focus, disabled) and theme
(Night, Day), its grab compared against a baseline, through VLC's own QML test runner (`modules/gui/qt/tests/
qml_test.cpp`, Qt Quick Test). Acceptance (ROADMAP): a sample widget passes in both themes and all states.

## Research (T1)
Starting point: `qml_test.cpp` runs Qt Quick Test offscreen with `tst_FSM.qml` (imports `VLC.Util`); it registers
nothing yet ("type registration & initialisation may be required later on").

Researcher report (T1), checked in the code and measured in the container:
- `qmllibs` already holds every QML module's resources (VLC.Style, VLC.Widgets, VLC.MainInterface); `qml_test` only
  initialises `util_assets`. The C++ types come from `MainUI::registerQMLTypes`: for a widget the test needs
  `ColorSchemeModel`, `ColorContext`, `colorProperty`, `SystemPalette`, `VLCIcons` (VLC.Style), the `MainCtx`
  singleton and the `Navigation` attached type (VLC.MainInterface).
- The sample widgets read `MainCtx` only through `VLCStyle`: `dp()`, `intfScaleFactor`, `colorScheme`, `safeArea`,
  plus `hasAcrylicSurface` and `intfMainWindow` (AcrylicController). The real `MainCtx` needs a running interface
  (playlist, settings, models), so the test uses a **stub `MainCtx`** behind a shadow header
  (`tests/stub/maininterface/mainctx.hpp`, first on the include path) and compiles its own copies of the style
  sources against it.
- `SystemPalette::componentComplete()` asserts `m_ctx` and reads `qt-accent-color` from the interface even for Day
  and Night: a one-line guard (no interface, keep the default accent) makes it usable without one. Upstreamable.
- Offscreen Qt Quick already renders with the software backend; hover needs `QT_QUICK_CONTROLS_HOVER_ENABLED=1`
  offscreen; `mouseMove` gives hover, `mousePress` pressed, `forceActiveFocus(Qt.TabFocusReason)` visual focus; two
  grabs are pixel-identical. No upstream QML widget tests exist; Qt's own baseline tests (Lancelot,
  `tests/baseline/controls`) need a server and are GPL-3/commercial: the per-state grab idea only.

## Plan (T2)
- **T3 harness:** stub `MainCtx`; `qml_test.cpp` initialises the style, widgets and main-interface resources,
  registers the types above, and forces offscreen software rendering with hover enabled; a `Baseline` singleton
  (`tests/qml_baseline.cpp`) grabs an item, compares it with `redux/qa/components/baselines/<name>.png` (per-channel
  tolerance), writes the actual image and a diff to `build/meson/l4/` on a failure, and writes the baseline when
  `REDUX_UPDATE_BASELINES=1` (Q0.4's update convention). Built by meson and autotools.
- **T4 sample widget:** `tests/tst_ButtonExt.qml`: Night and Day × normal, hover, pressed, focus, disabled.
- **T5:** `qa.sh` reports the QML component tests as `l4.<test>` (they run with VLC's test suite in L3), cases,
  docs (D34), QC.
